# 第 2 步 · 寻源

## 目标与完成标准

竞品分析、行业调研、情报收集是寻源的原料；寻源的终点是**具体的人**。情报帮你看懂外面，寻源负责落到人。

| 层 | 做什么 | 产出 |
|---|---|---|
| 1 情报 | 看懂外部：竞品动态、人才地图、行业大会、公开分享 | 地图、判断、假设 |
| 2 定位 | 找到哪个团队、哪个人在做你关心的事 | 目标团队与具体的人，附可核实的线索、来源与待验证项 |
| 3 落成名单 | 找到联系方式，标好证据，交给第 3 步 | 名单或样本 |

只做到第 1 层，没有落到人，第 2 步不算走完。

两条线的终点不同：
- **岗位线**：一批能拿去换反馈的**样本**，而不是一份按自拟画像拉的名单。完成标准：用人方对样本给出了具体的「要 / 不要 + 为什么」。
- **行业交流线**：做过这件事的人，附公开成果作证据。完成标准：能说清楚他做过什么、与一号位关心的问题对得上在哪。

长期人才关系也可以从寻源开始，不要求当下有岗位或必须安排一号位交流。没有公开作品时，可通过专家引荐、本人交流中自愿分享的非保密经历等形成线索；标明来源与未知，不把公开曝光度作为发现人才的门槛。

## 判断点

### 与第 1、3、5 步的分工

| 步骤 | 负责什么 |
|---|---|
| 第 1 步 | 确认要解决什么、要求是否成立。寻源发现需求矛盾时带证据回第 1 步，不自行改门槛 |
| 第 2 步（本步） | 用市场证据定位团队和具体的人，检验寻找路径；交付值得进一步了解的人与依据 |
| 第 3 步 | 和人建立、经营关系；交流中补到的证据回流第 5 步 |
| 第 5 步 | 依据多场景证据判断能力、属性、是否值得长期投入。发现线索不等于评估通过 |

步骤可以往返：寻源先形成可继续了解的线索，不要求联系前完成全面评估；评估结果再反过来调整寻源方向。

### 寻源判断速查表

按当前情况选行核对，不必逐项问完。

| 看到 / 听到什么 | 先核对什么 | 应形成什么判断 / 动作 |
|---|---|---|
| 任务明确，却不知道从哪类人找 | 哪些团队解决过同类问题？业务阶段、规模和资源条件可比吗？ | 形成按问题划分的人才方向与证据；任务不清回第 1 步 |
| 只有名校、大厂、头衔或项目标签 | 标签对应哪项任务证据？是否漏掉不同背景但做成同类事情的人？ | 标签用于召回和形成假设；背景替代假设带回第 1 步确认，不自行改门槛 |
| 团队很强，却找不到真正做事的人 | 谁是负责人、接口人、实际承担者？公开材料能否支持个人贡献？ | 定位具体角色和人；贡献未知标待验证，不用项目成绩代替个人能力 |
| 拿到很多零散信息，但说不清意味着什么 | 每条的来源与日期？当前任还是曾任？多份消息是否来自同一原始来源？ | 停止继续堆信息，记入下方「行业线索记录与核实」表；无法确认的保持未决，不拼成当前组织事实 |
| “市场上没有”或搜了一轮没结果 | 查过哪些方向、渠道、关键词？筛掉了谁、为什么？信息是缺失还是明确不满足？ | 继续补覆盖 / 补证据 / 带供给样本回第 1 步讨论取舍；不把未找到当不存在 |
| 名单很多，却全来自同一圈子 | 来源是否独立？是否只有同类公司、同一专家或同批转载？ | 补相邻能力来源和不同方向样本；不把重复推荐当多份独立证据 |
| 想发岗，或单一渠道迟迟没结果 | 目标人在哪留下成果、通过谁能定位？卡在发现人、核实信息还是建立联系？ | 按缺口选下一渠道；不默认靠发岗等投递，平台可主动搜索、找样本、测市场，联系交第 3 步 |
| 遇到陌生领域，或专家意见不一 | 判断基于什么证据、哪种环境？分歧是事实、标准还是圈层偏好？ | 先找领域专家网络聊，没有就建；建议每个领域 2–3 人，人数不能代替核验，分歧本身是信息 |
| 想系统研究目标公司或竞品团队 | 研究目的是什么？ | 看项目 / 组织 / 人才 / 时机四层 → [人才地图与竞品动态监测](../references/talent-map.md) |
| 竞品出现上线、重组、收缩、离职去向 | 事件核实了吗？能支持什么供给判断，还有什么解释？ | 更新地图与复查节点；只作为研究窗口，不推断个人意愿，动机交第 4 步 |
| 内部核心人才要离职 | 他去哪里？ | 主动关心去向，记入人才地图作为竞品信号，并保持联系 → [人才地图 · 内部核心人才的流向](../references/talent-map.md) |
| 做了很多研究，仍没有具体的人 | 卡在团队定位、角色定位还是身份确认？ | 针对缺口补证据或引荐路径；只做情报不算完成寻源 |
| 样本被连续否决，或各方反馈冲突 | 样本可比吗、呈现充分吗？否决依据一致吗？业务目标或决策标准变了吗？ | 补信息 / 换样本 / 带分歧回第 1 步由拍板人确认，不继续堆条件 |
| 岗位硬门槛还没确认，或部分信息查不到 | 名单用于校准还是正式推进？缺的是需求确认还是个人证据？ | 可做研究样本，未知不记为不达标；不以岗位名义对外触达（硬规则 2）；无岗位交流如实说明来意，按第 3 步处理 |
| 继续搜索却不再增加有效信息 | 还有哪些未覆盖路径？下一轮能检验什么假设？未决问题是否需要用人方取舍？ | 有新验证方向则继续；否则交阶段结论与覆盖缺口，回第 1 步校准，不宣称穷尽市场 |

每轮保留：**搜索覆盖与来源 / 已确认事实 / 当前判断 / 未知与其他解释 / 下一步验证 / 是否需回第 1 步**。这张表不替代第 4–5 步的动机核实和能力评估。

## 模板

- **标签只负责召回**：学校 / 公司 / 职级 / 项目 / 地域。
- **硬门槛负责过滤**：没有它就不能解决当前问题的技能与经验。
- **属性与动机按第 4–5 步验证**：寻源可记录初步信号与未知，不从标签直接推断「优秀」「稳定」「有潜力」。
- **人才地图与动态预警**：[references/talent-map.md](../references/talent-map.md)。
- **样本反馈记录**：复用 [第 1 步模板 5“样本反馈与共识记录”](01-intake.md)，附本轮搜索覆盖、来源与日期；反馈引起需求调整时，回填需求澄清表并保留版本。

### 渠道选择：不只盯招聘平台

高招岗位的人，很多不在招聘平台上活跃。硬规则 4 限制的是“把公开发岗当主路径”，不排除在平台上主动搜索。

| 渠道 | 怎么用 | 适合 |
|---|---|---|
| 行业大会、论坛、线下沙龙 | 用 AI 检索今年本领域的会议和议程，挑讲者和参会团队对口的场次，到现场交流、换联系方式 | 一线实践者、技术专家；也适合行业交流线 |
| 游戏行业展会与开发者沙龙 | 到展位体验作品、听开发者分享，从具体作品和实践问题聊起，双方愿意时交换联系方式 | 一线开发者、独立团队与项目负责人；也适合认识尚未被广泛关注的实践者 |
| 公开分享与作品 | 大会演讲、论文、开源项目、技术博客、作品集 → 找作者 | 做过某件事、有证据的人 |
| 行业媒体与编辑推荐 | 读游戏葡萄等游戏媒体公众号的专访，从文末编辑公开的联系方式建立联系；请编辑引荐采访对象，或推荐了解该领域的实践者 | 项目负责人、制作人等平台上难找到的人；也适合行业交流线 |
| 自有社交媒体与互动 | 经营微信朋友圈、小红书、B 站等，持续分享专业观察与实践思考；从评论、私信和长期互动中发现值得了解的人 | 可持续的人才入口，发现主动靠近或尚未进入招聘流程的潜在 Star Candidate |
| 内部对外岗位的同事 | 找持续连接开发者和项目团队的同事，如平台型业务的开发者运营、商务、大客户管理团队，请其引荐熟悉的开发者、项目负责人和行业人士 | 需要熟人引荐的开发者、项目负责人及公司高层 |
| 团队招聘同学的信息互通 | 平时多交流各自的岗位、人选、市场发现与外部联系；遇到推荐或线索缺口时，知道可以找谁协作 | 跨岗位推荐、信息互补、借助已有关系建立联系 |
| 内部午餐局与咖啡交流 | 常约 HR 团队同事、业务关键合作人吃午饭、喝咖啡，交换在用的 AI 工具、外部行业信息、业务近况和人才线索 | 发现业务新问题与人才线索、获得推荐、校准判断 |
| 领域专家网络 | 找内部和外部专家推荐他们认可的同行 | 圈内口碑好、平台上找不到的人 |
| 猎头 | 给清楚的硬门槛，让猎头定向寻访；平时长期维护关系 | 时间紧、需要大范围扫描时；好猎头也会主动推荐平台上找不到的人 |
| 招聘平台主动搜索 | 在 BOSS 直聘、脉脉等平台，按业务问题对应的能力、项目、公司与岗位关键词主动搜索，核对实际经历，形成具体人选与待验证项 | 找相关实践者、补充样本、校准供给；不把平台可见结果当完整市场 |

**招聘平台主动搜索**：
- 从要解决的问题出发，组合能力、项目经历、目标团队与岗位同义词搜索，不只搜一个职位名称；学校、公司、头衔用于召回，不能直接证明能力。
- 记录人选来源、查看日期、匹配依据和未知项；与其他渠道去重。搜不到或资料不全，不直接记为市场无人或能力不达标。
- 搜索与联系分开：形成名单后，按第 3 步准备联系理由；岗位门槛未确认时不以岗位名义触达。本段只沉淀方法，不自动搜索、加好友或发消息。

**自有社交媒体**：
- 让相关人选有机会看见你的专业关注并持续互动。按自己的表达方式与目标人群选平台，不要求同时经营所有账号。
- 从互动内容中看对方做过什么、怎么分析问题、能否给出有实践依据的观点；记下值得进一步了解的理由，进入第 3 步交流，再按第 5 步验证。
- 档案里分别记“最初从哪个账号或内容认识”与后续进展；点赞量、粉丝数、互动频率或对你的认可都不是能力证据。内容经营与关系互动见 [第 3 步](03-engage.md)。

**线下活动前后**：
- 会前：看议程和讲者名单，标出 3–5 个想认识的人，想好每人一句和他工作相关的开场。
- 会上：先聊他的分享和工作，不先递岗位（第 4 步「先问他，再讲 JD」）。
- 会后 48 小时内：跟进联系，记下聊了什么、他关心什么；归入岗位线或行业交流线。

**游戏行业展会与开发者沙龙**：
- 会前看参展团队、作品和分享议程，挑出相关开发者；也给现场发现陌生作品和团队留空间。
- 现场说明身份，从作品中的具体设计、技术或开发取舍聊起，了解对方实际负责什么；不因作品亮眼就判定个人能力。现场忙时尊重接待节奏，另约时间。
- 会后围绕聊过的内容跟进；有匹配岗位按第 3 步推进，没有岗位也可维持长期关系或安排行业交流。

**猎头关系要平时养，不是有岗才找**：
- 定期请本领域的猎头来公司吃饭、交流，让他们了解公司在做什么、需要什么样的人；节假日保持联系。
- 收到推荐要及时反馈结果，不让推荐石沉大海。
- 留意猎头在朋友圈等日常动态里透露的人选意向，看到匹配的主动请其引荐。
- 合作边界：推荐费按合同；不通过猎头打听候选人所在公司的机密。

**行业媒体编辑也要长期维护**：
- 从具体文章切入申请添加，说明你是谁、为什么对采访对象的哪段实践感兴趣、希望进行什么交流；没有公开联系方式时，用媒体公开的渠道，不假定每篇文章都有微信。
- 编辑愿意交流后，请其判断是否方便引荐采访对象；添加编辑不等于采访对象已同意被联系。
- 专访本身就是情报：项目做到哪一步、负责人怎么想、团队缺什么，都能从中读出来。
- 编辑是可以长期合作的引荐人，不是一次性拿联系方式的工具。平时可以提供行业交流、选题线索，有来有往。
- 尊重对方意愿，不勉强；编辑给的联系方式只用于说明过的来意，不转给别人。

**请内部对外岗位的同事引荐时**：
- 先找与目标人群有日常联系的团队，说明想了解的领域、项目或具体的人；不只找负责人，也可以找实际维护该开发者或项目关系的同事。
- 他们的客户关系是业务资产。先说清来意（行业交流还是招聘），由他判断合不合适、怎么介绍。
- 不能影响他和客户的合作：对方是合作方、客户时，不以挖人开场，优先走行业交流线。
- 聊完把结果同步给引荐的同事，不让他在客户面前被动。

### 多和团队招聘同学聊天，让信息形成连接

平时主动和团队招聘同学交流，让彼此了解正在招什么、聊过哪类人、有哪些新发现，以及近期和哪些外部同行或团队有联系。这些信息当下未必有用，后来可能帮助岗位校准、人选推荐或补齐线索。

- **让同事知道你能连接什么**：例如近期与某类公司的 HR 交流较多、熟悉某个领域的人才。说明可协助的方向，不需要把外部联系人的信息散发给团队。
- **也了解同事正在找什么**：遇到不适配自己岗位、却可能适合别人岗位的人选或信息时，能想起具体同事。
- **遇到缺口再连接关系**：有履历但缺联系路径时，看看团队里谁与相关公司有联系，由熟悉的一方询问是否方便引荐；获取和使用个人联系方式时确认可分享、可联系的范围。
- **结果回流**：补齐线索、建立联系或推进面试后，把进展同步给协作同事；候选人继续使用统一主表记录，保留发现来源与协助路径。

例：日常聊天中，一位招聘同学得知另一位同事近期与某公司的 HR 联系较多。后来他找到一份没有联系方式的简历，候选人曾在那家公司求职，于是请这位同事向该公司 HR 询问联系路径，最终获得联系方式、完成触达并推进面试。

### 内部午餐局：在非正式交流里接上内外部信息

常和 HR 团队同事、业务关键合作人组午餐局，比如在公司食堂吃完饭再一起喝杯咖啡。正式会议多讨论已确定的事；轻松的饭局更容易聊到各自在用的 AI 工具、外部行业动态、业务最近卡在哪里，以及认识或聊过的人。

- **约谁**：招聘、BP 等同事，以及业务中经常协作、了解一线问题的关键人。人员轮换，不只和熟人吃饭；不必每次围绕具体岗位。
- **聊什么**：交换 AI 工具与做法、行业信息、业务近况；自然了解对方在找什么人、认识谁，也分享你能连接的资源。先把自己的新发现拿出来，不把饭局变成单向打听。
- **怎么用到寻源**：聊到的业务问题回第 1 步核对需求；提到的人、团队、公开分享，按本步渠道继续找证据和联系路径；适合别人岗位的线索及时转给对应同事。
- **会后怎么记**：当天把可行动的信息记入下方「行业线索记录与核实」表，标来源和待验证项。饭局闲聊先当线索，不直接当事实或业务结论。
- **边界**：候选人隐私、薪酬、未公开的组织安排，只在必要范围交流，不在公开场合转述；对方随口提到的信息，用于对外沟通前先确认可以使用。

### 行业线索记录与核实

把零散线索记下来，分清看到或听到了什么、自己推测了什么，以及下一步怎么核实。

| 事实（原始信息） | 当前假设 | 其他可能解释 | 下一条最省力的验证 |
|---|---|---|---|
| 只写看到 / 听到的，不解释 | 这条信息可能意味着什么 | 至少保留一个竞争解释 | 一个问题、一个样本或一个旁证 |

碎片越多，不代表判断越准。没有形成可验证假设的信息，只是库存。

### 领域专家网络

每个关键领域，找到 **2–3 位**（建议节奏）你亲自聊过、确认很强的专家。之后遇到这个领域的事，第一时间找他们。

| | 内部专家 | 外部专家 |
|---|---|---|
| 是谁 | 公司内部公认在这个领域长期稳定产出的人 | 外部聊下来很强的候选人，作为顾问保持联系 |
| 需求澄清 | 判断岗位真正要什么、哪些是硬门槛 | 告诉你市场上做到什么水平算强 |
| 寻源 | 推荐他认可的同行 | 告诉你谁真正做过、哪些团队强 |
| 评估 | 参加专业面，校准判断 | 侧面了解这个领域的真实水平 |
| 行业交流线 | 陪一号位交流，把关专业深度 | 本身就可以是交流对象 |

**台账字段**：领域 / 专家（内部或外部）/ 擅长判断什么 / 怎么认识的 / 上次交流时间 / 他给过的判断和后来的结果。

**规则**：
- **不靠一个人下判断**。意见不一致时，分歧本身就是信息。
- **警惕专家的圈子和来源环境**：他推荐的人通常和他相似；他的标准可能来自上一家公司。
- **外部专家要有来有往**：给真实价值，比如交流、认可，必要时付顾问费，不长期免费索取。不向他透露公司内部信息，也不打听他所在公司的机密。
- **定期对账**：专家判断过、推荐过的人后来表现如何？长期不准的，换掉。
- **真实姓名只记在本地人才库**，不写进本 skill。

### 年度关键链接人

每年围绕当年的高招主题，发展一位能持续带来增量的关键链接人（建议节奏）。这类人像“现实版的 AI”：通过经常交流，帮你更早获得信息、理解变化、连接资源，放大个人的信息与判断能力。

关键链接人的价值往往在后续交流中才显现，初识时先保留观察，不急着认定或否定，也不以早期回应冷暖定性。

- **先定主题再识别人**：今年重点招什么、研究什么，自己最缺哪类信息、实践判断或关系网络？关键链接人的长处要和这个主题密切相关。
- **看实际增量**：他是否在相关领域持续实践、接触一手信息？交流中是否带来你原来不知道、且能帮助行动的信息、判断或连接？不只看头衔或认识的人多不多。
- **跨年继续维护**：已有的关键链接人不因跨年更换，也不为凑数贴标签。
- **与候选人、专家角色分开**：关键链接人可以是同行 HR、从业者或其他相关领域的人，不要求是候选人，也不自动评为 Star。专家网络侧重具体领域的专业校准；关键链接人侧重年度主题下持续的信息、视野和资源增量，两种角色可以重合。

例：当年主题是 AI 高招，新认识一位持续深入使用 AI 的同行 HR，对方能及时分享工具实践和行业信息；双方持续交换，帮助彼此更快理解与行动。

交流方式见 [第 3 步 · 年度关键链接人](03-engage.md)。

### 关键链接人登记

和统一候选人主表区分管理：可以单独建一张登记表，也可以在统一人才档案里用“关系类型 = 关键链接人 + 年度”打标记。每位链接人一条持续更新的记录，跨年追加主题与进展，不重复建人；若对方同时是候选人，候选评估与链接人增量分别记录。

| 字段 | 记录内容 |
|---|---|
| 关键链接人 / 认识来源 | 本地身份标识、如何认识、开始交流日期 |
| 年度主题与互补长处 | 和哪一年的高招主题相关，擅长什么，补足你的哪个信息或判断缺口 |
| 预期增量 | 可能持续提供的信息、实践判断或资源连接；预期与已发生事实分开 |
| 实际增量信息 | 何时分享了什么、来自什么实践或来源、对你有什么价值；后续验证或应用结果，未核实的标待验证 |
| 人脉关系 | 他能通往哪些人或公司（同学、前同事等），动用前先征得他同意 |
| 双向交换 | 你能提供什么，近期实际交换过哪些信息、帮助或连接 |
| 交流节奏 | 适合的联系频率与方式、最近交流日期、下一次交流时间或触发条件 |
| 后续话题与维护 | 下次值得讨论的问题、约定动作、最后更新日期 |

每次有价值的交流后补记增量与后续安排。频率按双方习惯约定，不统一设成每周或每月。个人身份与具体交流内容只留本地，skill 只保留通用字段。
