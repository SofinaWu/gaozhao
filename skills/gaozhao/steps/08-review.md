# 第 8 步 · 复盘与沉淀

## 目标与完成标准
- 每个岗位结束后，判断与结果对上一次账
- 完成标准：至少产出一个按 `cases/_template.md` 写的去公司化案例，或一条对本 skill 的修改建议

## 判断点
| 信号 | 走向 |
|---|---|
| 判断准了 | 记下当时靠的是哪个信号 |
| 判断错了 | 记下当时漏看或误读了哪个信号，回写到对应步骤的判断点 |
| 偏离了默认做法 | 检查当时写下的理由是否成立 |
| 同事会背模板，但遇到真岗不会判断 | 不再加知识点，改用真案带教闭环 |
| 本月还没给公司或业务一号位安排行业交流 | 回到业务方近期在聊的问题，从第 2 步找公开成果和作者 |

## 模板
- 闭环：见 `talent-read` 第 5 步
- 案例模板：`cases/_template.md`

### 真案带教闭环

理论是积累，真岗才是考场。师父不替徒弟下结论，也不让他无保护地试错：

1. **行动前**：徒弟先写事实、当前假设、竞争解释和下一条验证。
2. **真场景**：由徒弟执行；涉及候选人权益、敏感信息或不可逆动作时，师父先把边界说清。
3. **行动后**：先让徒弟复盘「我当时为什么这么判断」，师父再指出漏看的信号。
4. **沉淀**：把新判断点、失败模式或案例回写到对应步骤。

带教看的是思路能否迁移，不是能否复述师父的标准答案。
