# 第 1 步 · 需求澄清

## 目标与完成标准
- 用人方要解决的业务问题说得出来，不只是一个岗位名
- 硬门槛（过滤）与属性（排序）分开写；排除条件 ≥3 条
- 完成标准：有一版用人方确认过的需求澄清表

## 判断点
| 信号 | 走向 |
|---|---|
| 没有 JD / 「先都看看」/ 新业务 等命中 ≥2 条 | 按 VUCA 跑 → `vuca-intake` |
| 有成熟 JD、方向清楚 | 常规流程，不必上本 skill |
| 用人方回避某些追问、强调保密 | 不硬追，做旁证（谁在兼这活、现有团队缺口） |
| 加分项被写成过滤条件 | 拆回来：底座是门槛，热点是加分（硬规则 3） |
| 用人方按「能干活、肯加班」描述一个高杠杆岗位 | 追问判断错一次的代价；杠杆越大，判断力权重越高 |

## 模板
- 必问 9 题、需求澄清表：见 `vuca-intake` 第 1–2 步

### 杠杆三问（判断这个岗位要买的是执行还是判断）

1. 这个人的产出会通过什么被放大：带团队、管预算、写代码，还是做内容 / 对外影响？
2. 他做错一个关键判断，最坏损失多大，多久才能发现？
3. 他的哪些决定可以不经上级拍板就生效？

放大越多、损失越大、自主权越高，越要在第 5 步重点看判断力和担责，而不是技能清单。
