# 第 1 步 · 需求澄清

## 目标与完成标准

### 目标

- 说清用人方要解决的业务问题，而不只是岗位名。
- 判断招聘能解决哪部分问题，哪些还依赖流程、授权或资源调整。
- 把期望结果转成岗位任务，再区分硬门槛（过滤）、属性（排序）与背景偏好。
- 形成一版用人方确认过的需求澄清表，保留分歧、未知和后续验证路径。

### 分阶段完成标准

澄清是持续收敛的过程。“足以支持当前动作”不等于全部条件已确定；入职验证也不是开始研究的前提。

| 当前阶段 | 足以推进的条件 | 下一步 |
|---|---|---|
| 可以开始研究 | 能描述业务问题、当前任务假设与关键未知；说明研究目的，知道找谁反馈 | 按动作 1–4 用样本做研究和校准，允许部分条件待定 |
| 可以以岗位名义交流 | 用人方确认硬门槛；岗位任务、已定条件和对外口径有依据，重要未知有明确说明，不作未获确认的承诺 | 按动作 5 开展交流；遵守主 skill 的外联授权要求 |
| 可以持续评估与推荐 | 有可验证的要求与面试分工；取得与当前环节相称的证据，双向适配风险和未验证项如实记录 | 按动作 6 及第 5、6 步推进，不要求初次推荐前完成所有后续面试 |
| 可以交接与回看 | 关键承诺与承接条件有负责人，约定按岗位见效周期验证贡献 | 按动作 8 到岗前交接、到岗后回看；不把 Offer 接受当作澄清全部完成 |

每阶段保留：当前共识、关键分歧与未知、负责人、验证动作和复查节点。硬门槛、属性、背景偏好分开记录，首要任务与权限、资源、时间和招聘条件相互对照。

## 判断点

### 入口：先定位需求状态

| 信号 | 走向 |
|---|---|
| 没有 JD / “先都看看” / 新业务等 | 转 `vuca-intake`，按具体模糊点选择动作 |
| 有成熟 JD、方向清楚 | 常规澄清；有 JD 本身不证明真实需求已对齐 |
| 用人方回避追问、强调保密 | 不硬追，可看谁在兼这项工作、现有团队缺口；旁证仍需标明来源与不确定性，不直接推定回避原因 |
| 加分项被写成过滤条件 | 检验缺少它是否会影响关键任务，再区分门槛与加分项 |
| 用“能干活、肯加班”描述高杠杆岗位 | 追问判断失误代价与自主权，结合下方“杠杆三问”确定岗位侧重 |

### 使用方式

九类判断解释回答，速查表帮助选用，“易漏环节”提示容易漏掉的事；详细操作统一见模板 7 的动作 1–8，记录写回同一份需求澄清表，不逐张另填。

**本步术语**

| 术语 | 本步含义 |
|---|---|
| 第 N 步 / 动作 N | “第 N 步”指整个 skill 的八个步骤；“动作 N”只指本步模板 7 内的推进动作 |
| 需求澄清表 | 本岗位唯一的需求记录，含版本；模板 2–6、8 都是它的字段或视图，不另建平行表 |
| 硬门槛 / 属性 / 背景偏好 / 待验证 | 硬门槛用于过滤，缺了关键任务会失败；属性用于排序；背景偏好可加分但不过滤；未经检验的要求先归待验证 |
| 样本 / 候选人 | 样本用于校准需求和比较方向，不等于正式推荐；以岗位名义交流后称候选人 |
| 用人方 / 拍板人 | 用人方是提出需求、参与评估的业务方；拍板人是对某项取舍有最终决定权的人，不一定是同一人 |
| 复查 / 回看 | 复查是每轮推进后的方向确认（动作 7）；回看是到岗后按岗位见效周期校验贡献（动作 8） |
| 统一候选人主表 | 本地维护的个人信息与评估记录；需求澄清表与 skill 只留去身份化的共性发现 |

下面九类按当前回答选用，不作为逐项审问清单。使用者是招聘或 HRBP 时，协助其判断、设计追问；不要默认使用者本人拥有业务授权。

先分清对方原话、可核实事实和招聘推断。信息不足时保留竞争解释，用一个追问、样本或旁证继续验证；不要把一个现象直接翻译成岗位类型或候选人硬门槛。

### 1. 听到“我们缺一个人”：招聘能解决多少问题？

**易错点**：把所有问题都解释成缺人，未区分人手、能力和组织条件。

**核对问题**：
- 工作有没有明确负责人？有，是工作量超载、能力不足，还是卡在其他人的决策？
- 换一个更强的人，能改变哪个具体环节？即使到位，哪些障碍仍存在？
- 若需同步调整流程、授权或资源，由谁负责兑现？

**应形成的判断**：缺人手、缺能力、组织条件不足，或几种问题并存。仅凭“需要人工兜底”不足以认定该招独立收口的人。

### 2. 听到“来了以后把这件事做好”：到底买什么结果？

**易错点**：把模糊愿望当成岗位结果，或默认所有岗位都按三个月见效。

**核对问题**：
- “做好”能否落到具体交付、行为或结果？哪些由本人控制，哪些依赖团队或市场？
- 首要任务是短期救火、建立机制，还是长期探索？
- 多个结果能否由同一人在同一阶段完成？冲突时先保什么？

**应形成的判断**：首要任务、阶段顺序，以及不能由该岗位单独承担的结果。期望结果还需转成能力证据，不能直接当筛选门槛。

### 3. 听到“必须有某种背景”：是真门槛还是背景偏好？

**易错点**：未经检验就把背景要求定成业务硬门槛。

**核对问题**：
- 这段背景具体提供什么能力、经验或资源？缺少它，会在哪个关键任务上失败？
- 其他经历能否提供同等能力证据？
- 是否愿意看背景不同、但做成过同类事情的样本？

**应形成的判断**：硬门槛、背景偏好或待验证。保留原话，不直接把标签定成门槛。

### 4. 听到“聪明、靠谱、有 owner 意识”：对应什么行为？

**易错点**：招聘替对方解释软性词后，没有交回确认。

**核对问题**：
- 能否分别举出满意与不满意的具体行为？
- 指的是识别问题、判断取舍、主动推进，还是及时汇报？
- 要求主动时，是否允许对方改变方案、挑战判断？
- 同一个词在不同任务里的要求是否一致？

**应形成的判断**：可观察、可验证的行为要求，并交回用人方确认。反复出现的词是线索，招聘的解释先作为假设。

### 5. 听到“上一位不行／某类人都不行”：过去的失败能迁移吗？

**易错点**：把一次失败直接推成某类人的稳定规律。

**核对问题**：
- 哪件事没做到，依据是什么？当时目标、资源、权限、评价标准是否明确？
- 是不会做、不愿做，还是条件限制导致做不到？
- 当前岗位与过去情境有哪些相同和不同？有没有同类背景却成功的反例？

**应形成的判断**：可复用的风险条件，或仅限过去情境的经验。负面经历不能未经检验就变成背景禁区。

### 6. 听到“资深、独立负责，但先从一块做起”：能力与职责匹配吗？

**易错点**：能力要求高，但职责、权限与交换条件无法匹配。

**核对问题**：
- 要资深是为完成高难任务，还是希望少指导、少管理？这块工作用得上哪些资深能力？
- “独立负责”包括哪些决定，哪些仍需负责人拍板？
- 范围较窄是长期还是阶段安排？扩大范围的条件是什么？
- 职级、薪酬和评价是否与实际约定匹配？

**应形成的判断**：能力要求、职责范围与交换条件是否匹配；哪些边界必须在招聘时说明。具体定级与 Offer 问题交第 7 步处理。

### 7. 听到“都可以看看”又连续否人：反馈说明了什么？

**易错点**：把每次否决都转成新增筛选条件。

**核对问题**：
- 否的是能力、业务方向、职责层级，还是标签？依据来自人选事实，还是样本信息不足？
- 不同样本是否足以比较、能区分关键因素？同一标准是否一致使用？
- 是需求逐渐清楚，还是业务目标发生变化？

**应形成的判断**：更新画像、补样本信息，或重确认业务方向。反馈与开场陈述对照验证，不每否一个人就增加一条条件。

### 8. 听到多位决策人要求不同：谁决定取舍？

**易错点**：将多方要求相加，没有解决互斥取舍和拍板责任。

**核对问题**：
- 各自负责什么结果、拥有什么决定权和否决权？
- 是对同一任务有不同偏好，还是各自要解决不同问题？
- 哪些要求能兼容，哪些必须取舍？谁负责最终排序？
- 未解决的分歧是否会导致招聘反复换方向？

**应形成的判断**：已达成共识、待拍板取舍与拍板人，不把多方要求简单相加成一个画像。

### 9. 听到回避、含糊或不愿承诺：未知是否影响推进？

**易错点**：把回避直接解释成内部关系问题，忽略其他可能。

**核对问题**：
- 是不知道、不便说、没有决定权，还是暂时不愿决定？目前有什么依据？
- 能否用具体场景或样本帮助表达？旁证支持到哪一步，哪些需本人确认？
- 未知影响的是寻源方向、候选人预期，还是入职承接？
- 能否带着这个未知推进？推进前需要谁确认、向候选人披露什么？

**应形成的判断**：可暂缓、需继续验证、必须先获得决定的问题，及其对当前动作的影响。

### 九类判断点速查表

按当前回答选行核对，不必逐项问完。信息不足时，记录当前假设和下一条验证，不急着定论。

| 听到什么 | 先核对什么 | 应形成什么判断 |
|---|---|---|
| 1. “我们缺一个人” | 现有人是忙不过来、不会做，还是卡在决策？换人后哪些障碍仍在？ | 缺人手 / 缺能力 / 组织条件不足 / 问题并存；需配套调整什么、谁兑现 |
| 2. “来了把这件事做好” | 具体交付是什么？本人能控制多少？救火、建机制、探索先保哪个？ | 首要任务、阶段顺序、不能由岗位单独承担的结果 |
| 3. “必须有某种背景” | 这段背景支撑什么关键任务？缺了会怎样？能否用其他经历替代？ | 硬门槛 / 背景偏好 / 待验证，并写验证方式 |
| 4. “聪明、靠谱、有 owner 意识” | 满意和不满意的行为各是什么？要求主动时，允许做哪些决定？ | 可观察的行为要求，交回用人方确认 |
| 5. “上一位／某类人不行” | 哪件事没做好？是不会、不愿，还是条件不支持？当前情境相同吗，有无反例？ | 可复用的风险条件，或仅限过去情境的经验 |
| 6. “资深、独立负责，先做一块” | 资深能力用在哪？能决定什么？范围何时变化？职级、薪酬、评价是否匹配？ | 能力、职责与交换条件是否匹配；招聘时须说明的边界 |
| 7. “都可以看看”却连续否人 | 否决依据是事实还是信息不足？样本可比吗，标准一致吗，业务目标变了吗？ | 更新画像 / 补样本信息 / 重确认业务方向；不逐次堆排除条件 |
| 8. 多位决策人要求不同 | 各自负责什么、谁能决定或否决？哪些要求冲突，谁定优先级？ | 已有共识、待拍板取舍与拍板人 |
| 9. 回避、含糊、不愿承诺 | 是不清楚、不便说、无权决定还是暂不决定？依据是什么？未知影响哪一步？ | 可暂缓 / 继续验证 / 先获决定；推进前需谁确认、披露什么 |

核对后留下五项：**已确认 / 当前判断 / 仍有疑点 / 下一步验证 / 推进影响**（记录格式见模板 2）。

### 易漏环节的执行位置

保留作漏项速查，详细做法只在对应动作展开；不用把同一问题重复询问或记录。

| 核对主题 | 到哪里执行 | 核对结果 |
|---|---|---|
| 业务事实 | 动作 1；动作 3 补专业校准 | 事实依据与仍有争议的解释 |
| 外招必要性、优先级和替代方案 | 动作 1 | 外招解决哪部分、何时需要、过渡安排 |
| 编制、预算、地点与时间可行性 | 动作 1 初核，动作 2 用市场验证 | 已定、待批、可调整项；具体审批交第 7 步 |
| 岗位真实吸引力与难点 | 动作 5 | 对外口径、卖点假设与本人反馈 |
| 面试验证分工 | 动作 4 约定，动作 6 回看证据 | 谁验证什么、怎么判断、还缺什么 |
| 版本变化同步 | 动作 7 | 新旧差异、受影响对象与后续安排 |
| 入职承接 | 动作 1 用模板 4 初核承接条件，动作 8 到岗前交接、到岗后回看 | 任务、资源、反馈人与实际贡献 |

## 模板

### 1. 需求澄清表（主记录）

沟通问题、需求澄清表与版本记录：见 [vuca-intake · 第 1–2 步](../../vuca-intake/SKILL.md)；用样本换需求见其第 3 步。本文件的模板 2–6、8 是需求澄清表按需使用的字段或视图，不另建多张表、反复填同一信息；模板 7 是推进动作，不是表格。

`vuca-intake` 中的数量与时间（排除条件条数、几个月见效、每周几位人选）是建议节奏，不是推进门槛，按任务、证据与岗位见效周期决定。软性词和反馈需要验证，回避保留多种解释；理念契合要具体化，不要求分析结论一律相同。

### 2. 回答后的判断小结

| 项目 | 记录内容 |
|---|---|
| 已确认 | 对方明确说了什么；哪些有事实支持，哪些只是已表达的要求 |
| 当前判断 | 目前更支持什么解释，依据是什么 |
| 仍有疑点 | 还存在哪些解释、矛盾或未知 |
| 下一步验证 | 用一个追问、样本或旁证区分解释 |
| 推进影响 | 影响当前哪个动作；需先确认、披露，还是可边推进边验证 |

### 3. 要求与业务原因对照

| 原话 / 要求 | 对应任务与业务原因 | 当前分类 | 可替代经历 / 放宽条件 | 验证方式与确认人 |
|---|---|---|---|---|
| 待记录 | 缺少它会影响什么 | 硬门槛 / 属性 / 背景偏好 / 待验证 | 待记录 | 待记录 |

### 4. 结果与承接条件对照

| 期望结果 / 阶段 | 本人可决定的范围 | 可用资源 | 对他人的依赖 | 未落实条件与确认人 |
|---|---|---|---|---|
| 待记录 | 待记录 | 待记录 | 待记录 | 待记录 |

### 5. 样本反馈与共识记录

| 样本方向 / 区别 | 用人方反馈及事实依据 | 支持什么判断 | 其他解释 / 下一步验证 |
|---|---|---|---|
| 待记录 | 不只记喜欢或不喜欢 | 待记录 | 待记录 |

每轮收尾记录：本轮共识 / 尚未解决的分歧 / 拍板人 / 对当前寻源与沟通的影响；在动作 7 复查时使用。方向调整时记录触发原因，保留旧版。

### 6. 杠杆三问：要把事做好的人，还是替你拿主意的人

1. 这个人的产出会通过什么被放大：带团队、管预算、写代码，还是做内容 / 对外影响？
2. 他做错一个关键判断，最坏损失多大，多久才能发现？
3. 他的哪些决定可以不经上级拍板就生效？

放大越多、损失越大、自主权越高，越要在第 5 步重点看判断力和担责，而不是只看技能清单。若责任大而授权小，先记录承接条件的矛盾。

### 7. 澄清后的推进动作 1–8

先沿用已完成的澄清结论，按尚未解决的缺口选择动作，不从动作 1 重做。条件已定但没有目标团队或样本时，直接进入动作 2 和第 2 步寻源；已有样本但标准有分歧时进入动作 4；已经在交流或评估时进入对应环节。只有缺失条件会改变下一步时才补问。

本段是第 1 步内部的推进顺序，称“动作 1–8”，不改变整个 skill 的八步编号。按最关键的未知选择动作，可以往返；动作 8 的交接在到岗前、回看在到岗后进行，不要求开始寻源前做完全部动作。与分阶段完成标准的对应：动作 1–4 支持“开始研究”，动作 4 确认硬门槛与对外口径后进入“岗位名义交流”（动作 5），动作 6 支持“评估与推荐”，动作 8 对应“交接与回看”；动作 7 贯穿各阶段。

多方向人才地图、专家校准、持续交流、面试反馈回填画像、需求升版和入职后回看，都能在本步案例中看到；以下把它们整理成可执行的动作。

#### 动作 1：核实业务问题，约定本轮验证与责任

- **怎么做**：看可访问的产品或交付，与当前承担者及用人方核对具体问题，复述理解请其纠正；比较不招的影响、内部调整等替代路径，确认外招承担哪部分、优先级、贡献节点与过渡安排。初核编制、职责职级、预算、地点、工作方式、到岗窗口的状态与确认人；具体审批交 [第 7 步](07-offer.md)。对照模板 4 初核到岗后的任务、权限与承接条件。最后约定本轮关键未知、反馈人、拍板人和复查时间。
- **留下什么**：当前理解、已定与待定条件、业务事实来源、替代方案、阶段性承接安排与本轮验证责任，写入需求澄清表（模板 4、8）；不在 skill 记录真实薪资或个人信息。
- **怎么往下走**：足以研究就进入动作 2；关键目标或决策权冲突时按判断点 2、8 核对，请拍板人取舍。部分条件未定可以研究，但不得冒充已确认岗位条件对外承诺。

#### 动作 2：把问题拆成人才方向，做小范围地图

- **怎么做**：分别写出“哪类人凭什么能力解决哪个问题”，按 [第 2 步 · 寻源](02-sourcing.md) 找具体团队和有差异的样本。用市场线索检验经历、职责、预算、地点和时间的组合，缺少资料标待验证。
- **留下什么**：方向、贡献假设、具体样本、来源日期、证据和未知；条件有冲突时列明可调整项及业务影响，不自行改门槛或承诺加钱。
- **怎么往下走**：不懂领域先走动作 3，已有可比较证据则走动作 4；可行性冲突带回动作 7 复查，需重新定条件时回动作 1。搜索无结果先查覆盖，不宣布市场无人。

#### 动作 3：找专家与团队同事校准人才假设

- **怎么做**：带具体问题和样本，请专家、招聘同事或 BP 核对能力是否有用、替代经历是否成立、现有团队能给什么；网络使用见 [第 2 步](02-sourcing.md)。没有样本但不懂领域时，也可先做此动作，再回动作 2。
- **留下什么**：意见、事实依据、来源环境、分歧与新线索。
- **怎么往下走**：修正假设后回动作 2 或带样本进入动作 4；调整已确认要求须由拍板人确认。专家意见不能代替用人方决定，多人转述同一来源不算独立验证。

#### 动作 4：比较样本、确认取舍与面试验证分工

- **怎么做**：让用人方对有差异、信息足够的样本排序并说明依据，讨论替代经历与可放宽项，样本反馈用模板 5、要求与业务原因用模板 3 记录；方法参照 [vuca-intake · 用样本换需求](../../vuca-intake/SKILL.md)。与专业面试官把优先要求转成“任务—能力或属性—证据—验证方式—负责人”，讨论达标、不达标的具体表现。区分方向探索交流与正式选拔，不自动新增考试或统一分数线。
- **留下什么**：已确认的硬门槛、属性排序、背景偏好、待验证项、对外口径及验证分工；多方要求互斥时记录待拍板取舍，不堆成更长条件表。
- **怎么往下走**：信息不足回动作 2，标准冲突回动作 1；硬门槛与对外口径经用人方确认后，按 [第 3 步](03-engage.md) 准备触达并进入动作 5。把候选人正式递给用人方时按 [第 6 步](06-handoff.md) 做当时的双向适配检查，无需等全部后续评估完成。

#### 动作 5：核对候选人期待，检验组织能否承接

- **怎么做**：先内部准备有依据的任务、条件、难点及对外可讲范围，形成“为何可能愿意来”的假设；这不等于先向候选人灌输卖点。实际交流按 [第 3 步](03-engage.md) 说明身份来意，按 [第 4 步](04-motivation.md) 了解本人期待，再介绍对应岗位信息，并对照模板 4 的结果、权限与资源。深层问题随信任和意愿逐步了解，不要求首聊拿齐。
- **留下什么**：本人原话与推断、被认可或不被认可的岗位价值、承接差距及待确认条件。当天记录在统一候选人主表；需求澄清表只留去身份化的共性发现。
- **怎么往下走**：个体错配就分流或保留关系，多例出现相同错配则带证据走动作 7。回应少、暂不看机会与明确退出分开记录，原因未知不替对方补原因，也不从一人外推整类人。

#### 动作 6：取得面试证据，校准能力与行为判断

- **怎么做**：按 [第 5 步](05-assess.md) 整理关键事件、专业交流与必要的工作样本；对抽象评价追问具体行为，与动作 4 的分工对照。专业能力由专业面试官核验，招聘组织与记录；分歧先辨认是事实、标准还是证据不足，再做最小验证。
- **留下什么**：个人评估、未决风险、判断分歧，以及可回填需求的共性发现；个人亮点不自动成为全岗新门槛。
- **怎么往下走**：证据不足补验证，要求有误或遗漏回动作 7。动作 5、6 随交流往返；正式推荐（第 6 步）可能发生在本动作前或其中，每轮推荐说明已有证据和未知，不将“全部面试完成”设为推荐前提。

#### 动作 7：复查结果、确认版本并同步影响

- **怎么做**：按“关键交付 / 核心发现 / 推进结论”复查，分开看覆盖、匹配、回应、交流与退出依据，兼看通过与未推进样本；不以少量样本强算规律。由拍板人确认继续、调整或停止；没有新信息时明确下一步能解什么未知，必要时约定暂停与恢复条件。
- **留下什么**：证据与其他解释、继续或停止项、下一轮验证及责任；方向或要求变化时按 [vuca-intake · 版本记录](../../vuca-intake/SKILL.md) 升版保留依据，未变化只记进展。将确认的新口径同步有关招聘、评估与寻访协作方；检查在流程人选的影响，关键条件变动时由获授权的人说明并重新确认意愿。
- **怎么往下走**：新方向回动作 2，待拍板事项回动作 1；继续候选流程按第 3–7 步相应环节处理。关键承接条件不成立、缺决策或优先级改变时由拍板人决定调整或暂停，不靠重复加量解决；不以 Offer 接受证明需求判断全部正确。

#### 动作 8：到岗前交接，到岗后校验实际贡献

- **怎么做**：到岗前将任务、边界、承诺和待落实条件交用人方及相关 BP，明确带入职的人、首项任务、资源与协作接口、反馈人和回看节点。到岗后按岗位见效周期了解双方反馈，对照历次任务与证据，依 [第 8 步](08-review.md) 对账；招聘跟踪承接责任，不代替业务设计全部入职工作。
- **留下什么**：承接交接记录、实际贡献、有效与无效标准、环境兑现情况，以及过程中或事后才明确的需求。
- **怎么往下走**：把可复用发现回写本步判断点或案例，区分组织条件、目标变化与识人失误。具体个人信息持续留在统一候选人主表，不搬入通用 skill。

### 8. 招聘可行性与验证安排补充表

作为需求澄清表的字段使用，只补缺项，不另建平行版本。阶段性未知写确认人、验证动作与时间；以下是字段示例，不要求全部填满才能做研究。

| 项目 | 记录内容 |
|---|---|
| 业务依据与替代方案 | 产品或交付事实、当前承担者反馈、不招的影响、已考虑的替代路径、选择外招的原因 |
| 时间与优先级 | 业务贡献节点、可行到岗窗口、与其他需求的优先级、到岗前的过渡承接人 |
| 招聘条件 | 编制状态、职级职责、预算口径、地点与工作方式、确认人；哪些已定、待批或可调整 |
| 真实吸引力与难点 | 能提供的任务、资源、授权与回报，不能提供的条件，对外可讲范围与确认人；实际交流后验证哪些有效 |
| 要求与面试验证 | 关键任务、能力或属性、达标及不达标证据、验证方式、负责面试官、尚未覆盖的证据 |
| 版本与影响 | 本轮变化、理由、确认人、应同步对象、对在流程人选的影响与处理状态 |
| 调整或暂停 | 当前卡点、继续验证的价值、待决事项、负责人、恢复或复查条件 |
| 入职承接 | 带入职的人、首项任务、必要资源、协作接口、反馈人、回看时间与未落实条件 |

这些字段服务于决策；真实使用中无助于行动的可删减。数值、节奏与验证深度按岗位确定，不变成固定审批清单。

## 案例

- [从制作人到增长方向：用市场反馈持续澄清需求](../cases/01-从制作人到增长方向-用市场反馈持续澄清需求.md)：从宽泛的业务助理需求出发，以市场交流检验内部承接空间，转向增长相关能力并继续探索海外发行；记录三轮方向变化及入职反馈，区分当时发现与事后分析。

后续继续按 [案例模板](../cases/_template.md) 补充，保留“最初说法 → 当时判断与竞争解释 → 验证动作 → 反馈 → 修正后的需求”，不补写未发生的结果。

优先待补类型：
- 表面缺人，实际卡在流程、授权或资源。
- 用人方说不清，通过不同样本逐渐收敛（已有一例，可补样本对比与原始反馈细节）。
- 口头要求与实际选择不一致。
- 多位决策人各要一种人。
- 要求很多，通过取舍识别真正硬门槛。
