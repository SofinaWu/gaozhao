# 第 5 步 · 评估分层

## 目标与完成标准
- 每条判断挂一条具体证据（L2 以上）
- 区分标签、自述和关键行为，不让低信度信息越权
- 候选人质量与关系状态分开写
- 完成标准：一份可以给别人看懂、可以被校准的分层结论

## 判断点
| 信号 | 走向 |
|---|---|
| 只能说「感觉不错」 | 退回读信号清单 → `talent-read` 第 2 步 |
| 用名校、大厂、头衔直接证明能力或品格 | 退回假设；标签只能用于召回 |
| 用涨薪幅度、头衔、名气证明「他做得好」 | 这些是附带结果；退回问：他该做的事，具体做得怎么样？ |
| 用候选人的自我评价直接下属性结论 | 标为待验证；去找关键事件 |
| 只有一个关键事件 | 不下稳定品格结论；再找不同场景交叉验证 |
| 多个关键事件重复出现同一行为 | 可以形成属性判断，并标注置信度 |
| 证据不足，但团队急着要结论 | 保持未决，写清缺什么证据；不拿确定口吻掩盖焦虑 |
| 聪明、有冲劲，但正直有疑点 | 正直是门槛，不是加分项；不靠能力抵消 |
| 岗位越模糊 | 属性权重越高 → `talent-read` 第 1 步 |
| 出现 serial complainer 信号 | 按雷达处理 → `talent-read` |

## 模板
- 候选人评估输出格式：见 `talent-read`「输出格式」

### 证据三级

| 级别 | 例子 | 能做什么 |
|---|---|---|
| 标签 | 学校、公司、职级、项目 | 形成假设，不能直接定性 |
| 自述 | 「我负责」「我抗压」「我善于合作」 | 形成待验证点 |
| 关键行为 | 利益冲突、失败、犯错、被质疑时实际做了什么 | 支撑属性判断 |

### 多场景交叉验证

同一个属性至少找两个不同情境。以「责任感」为例：

- 项目失败时，他把原因归到哪里？
- 与上级意见冲突时，他如何处理？
- 自己犯错后，是隐藏、解释，还是修复？
- 团队成员出错时，他怎样分配责任？

一次回答可以被准备。看重复模式，不看一次表演。

### 高杠杆岗位额外三看

第 1 步判定为高杠杆岗位时，补看三项，每项都要有关键事件做证据：

| 看什么 | 问法示例 | 好信号 |
|---|---|---|
| 判断力 | 「讲一个信息不全时你做的决定，后来结果怎样？」 | 说得出当时的取舍和依据，事后能如实承认对错 |
| 担责 | 「有没有一件事，失败了责任在你名下？」 | 敢以自己的名义承担风险，失败后谈修复，不推脱 |
| 杠杆 | 「你的产出是怎么被放大的？」 | 能通过人、资源、系统或内容放大结果，而不只是自己多干 |

正直、智力、精力三者里，正直是前提。没有正直，另外两项越强，风险越大。

### 竞争性假设

同一行为至少保留两个解释，再设计最小验证：

> 事实：候选人连续两次推迟交流。  
> 假设 A：意愿低。  
> 假设 B：当前项目进入关键节点。  
> 验证：不追问态度，直接给两个更晚的时间窗口，看他是否主动选择或提出替代时间。

判断格式：

> 目前更支持 `<假设 A>`，证据是 `<事实>`；仍不能排除 `<假设 B>`；下一步用 `<最小验证>` 区分。

单条信息被推翻时，不是「候选人变了」，先检查自己的模型是否错了。
