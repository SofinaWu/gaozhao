# 第 5 步 · 评估分层

## 目标与完成标准
- 每条判断挂一条具体证据（L2 以上）
- 区分标签、自述和关键行为，不让低信度信息越权
- 候选人质量与关系状态分开写
- 完成标准：一份可解释、可校准的阶段性评估，写清当前分层（可未定）、证据缺口和下一步

## 判断点
| 信号 | 走向 |
|---|---|
| 只能说「感觉不错」 | 退回读信号清单 → `talent-read` 第 2 步 |
| 用名校、大厂、头衔直接证明能力或品格 | 退回假设；标签只能用于召回 |
| 用涨薪幅度、头衔、名气证明「他做得好」 | 这些是附带结果；退回问：他该做的事，具体做得怎么样？ |
| 用候选人的自我评价直接下属性结论 | 标为待验证；去找关键事件 |
| 只有一个关键事件 | 不下稳定品格结论；再找不同场景交叉验证 |
| 多个关键事件重复出现同一行为 | 可以形成属性判断，并标注置信度 |
| 证据不足，但团队急着要结论 | 评估状态记“待验证”，分层可未定；给已有依据、缺口、下一条验证及当前可推进环节，不把未知当不匹配 |
| 门槛达标、未见扣分，但只有一条可信属性信号 | 先给“待验证”的阶段性判断，继续专业面或补不同情境的关键事件；不凑加分条数，不直接归为“观察＝不匹配”或淘汰 |
| 聪明、有冲劲，但正直有疑点 | 正直是门槛，不是加分项；不靠能力抵消 |
| 岗位越模糊 | 属性权重越高 → `talent-read` 第 1 步 |
| 出现 serial complainer 信号 | 按雷达处理 → `talent-read` |

### 相识于微时 · 早期识别

持续接触同一领域的人，才能建立比较标尺，并在外部头衔、声望尚未形成时，识别值得长期投入的人。聊 100 人、挑出 10–20 人是示意，重点是广泛接触后的选择性判断，不是按比例必须选够。

| 核对什么 | 判断依据与边界 |
|---|---|
| 为什么认为他突出？ | 记录相对于同类人的具体能力、实际贡献与关键行为；不能只凭投缘、表达好或自述定性 |
| 优势是否有重复证据？ | 用已有的多场景交叉验证，区分单次亮点与重复表现；证据不足标待验证，不提前盖章 |
| 是尚未被看见，还是自己尚未了解？ | 外部知名度与能力分别记录。缺少名气不证明有潜力，知名度高也不降低能力评价 |
| 是否适合长期投入？ | 区分“值得长期关注”与“适配当前岗位”；没有当下岗位也可保持关系，有长期潜力也不豁免岗位门槛 |

当时写清“看好什么、依据是什么、仍有哪些未知”，后续把实际成长与当初判断对照，按第 8 步复盘更新标尺；不能因后来成功就倒推当时所有判断都正确。长期交往的投入方式和互惠边界见 [第 3 步 · 相识于微时](03-engage.md)。

### 月度 Star Candidate 标注

每月从已交流、已有证据的人选中，标注 3–5 位本月重点深聊的 Star Candidate，依据本步骤与 `talent-read` 的分层标准，并写清看好什么、证据是什么、还有什么需要验证。人数是关系投入的建议节奏，不是 Star 评定配额；证据不足的人标待验证，不为完成月度数量提前升级。

这份标注区分两件事：**候选人分层**与**本月投入安排**。已评为 Star 但本月未见面，不因此降级；暂不适配当前岗位但值得长期关注的人，也可纳入。将本月重点名单交 [第 3 步 · 每月 Star Candidate 面对面深聊](03-engage.md)，用实际交流补充证据和理解，再更新判断。见面频率、关系亲近程度、是否推荐他人，不作为能力或品格的替代证据。

## 模板
- 候选人评估输出格式：见 `talent-read`「输出格式」

### 所有候选人统一主表与个人档案

所有候选人的档案统一放在本地人才库的一张主表管理，每人一条主记录，使用唯一标识去重；跨岗位、跨渠道或跨月份再次接触时更新原记录，不重复建档。个人档案指主表中该候选人的记录与交流时间线，不再为每位 Star 单独维护一套档案文件。

通过分层、领域、岗位、推荐来源、当前进展和下次跟进日期筛选不同视图；Star Candidate、本月重点深聊名单都从同一张表筛出，不复制成独立维护的名单。所有候选人使用相同字段，Star 的判断证据与长期交流记录可更深入；未知项留空或标待验证，不要求每次交流问完所有字段。

| 模块 | 记录内容 |
|---|---|
| 基本信息与当前状态 | 唯一标识、身份、擅长领域、当前公司 / 项目 / 职责、关联岗位（如有）；信息来源及确认日期 |
| 看好的依据 | 评估状态（本轮证据足够 / 待验证）、当前分层（可未定）、具体能力与行为证据、判断日期、置信度和下一条验证；岗位不匹配与证据不足分开，调整时保留原判断与理由 |
| 期待与约束 | 本人自愿表达的职业期待、关注问题、意愿与时间约束；原话与推断分开，注明日期 |
| 认识与推荐来源 | 最初发现渠道、推荐人或引荐路径、日期、推荐理由；多次推荐按时间追加，保留最初来源，不覆盖旧记录 |
| 交流与进展时间线 | 每次沟通日期及方式、本人新进展、岗位推进状态（如有）、双方约定、提供过的信息或连接；区分本人确认与其他来源线索 |
| 对外推荐线索 | 对方自愿推荐过谁、何时推荐、为何认可、线索后续状态；与“谁推荐了他”分开记录，被推荐者另行验证 |
| 下次跟进与维护 | 下一次交流的理由、约定时间或复查节点、最后更新日期、最后核对日期 |

**更新节奏**：深聊、项目或职业状态变化、收到新推荐、判断发生调整时及时更新；每月安排重点深聊时一并复查档案，按各人约定的节点跟进。没有新信息不编造进展，也不把旧信息默认当作现状。

**维护边界**：档案中的姓名、联系方式、动机、薪资等具体个人信息只留在本地人才库，不写进 skill 或对外材料；只记录为判断和关系维护所需、对方自愿分享的信息。推荐来源与关系亲近程度不替代能力证据，更新档案也不代表获得联系或转发信息的授权。

每月按 [第 8 步 · Star Candidate 月度复盘](08-review.md) 对照新证据检验原判断，记录分层、适配或意愿的变化，并确定下一步；复盘记录回填本档案。

### 证据三级

| 级别 | 例子 | 能做什么 |
|---|---|---|
| 标签 | 学校、公司、职级、项目 | 形成假设，不能直接定性 |
| 自述 | 「我负责」「我抗压」「我善于合作」 | 形成待验证点 |
| 关键行为 | 利益冲突、失败、犯错、被质疑时实际做了什么 | 支撑属性判断 |

### 多场景交叉验证

同一个属性至少找两个不同情境。以「责任感」为例：

- 项目失败时，他把原因归到哪里？
- 与上级意见冲突时，他如何处理？
- 自己犯错后，是隐藏、解释，还是修复？
- 团队成员出错时，他怎样分配责任？

一次回答可以被准备。看重复模式，不看一次表演。

### 高杠杆岗位额外三看

第 1 步判定为高杠杆岗位时，补看三项，每项都要有关键事件做证据：

| 看什么 | 问法示例 | 好信号 |
|---|---|---|
| 判断力 | 「讲一个信息不全时你做的决定，后来结果怎样？」 | 说得出当时的取舍和依据，事后能如实承认对错 |
| 担责 | 「有没有一件事，失败了责任在你名下？」 | 敢以自己的名义承担风险，失败后谈修复，不推脱 |
| 杠杆 | 「你的产出是怎么被放大的？」 | 能通过人、资源、系统或内容放大结果，而不只是自己多干 |

正直、智力、精力三者里，正直是前提。没有正直，另外两项越强，风险越大。

### 竞争性假设

同一行为至少保留两个解释，再设计最小验证：

> 事实：候选人连续两次推迟交流。  
> 假设 A：意愿低。  
> 假设 B：当前项目进入关键节点。  
> 验证：不追问态度，直接给两个更晚的时间窗口，看他是否主动选择或提出替代时间。

判断格式：

> 目前更支持 `<假设 A>`，证据是 `<事实>`；仍不能排除 `<假设 B>`；下一步用 `<最小验证>` 区分。

单条信息被推翻时，不是「候选人变了」，先检查自己的模型是否错了。
