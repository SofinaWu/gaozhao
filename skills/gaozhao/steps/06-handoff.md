# 第 6 步 · 递给用人方

## 目标与完成标准
- 先判断这位用人方能给什么、不能给什么，再决定递谁、怎么递
- 同时判断这个环境能否满足候选人对下一份工作的期待，并支持他的工作方式
- 完成标准：给出与当前推荐环节相称的双向适配依据，明确已确认条件、未验证项及下一步

## 判断点
| 信号 | 走向 |
|---|---|
| 还不知道这位用人方的否决规则 | 核对当前岗位要求、业务原因与确认人；偏好和硬门槛分开，未知保持待确认，不套用其他负责人的规则 |
| 人选因项目关闭、优化或协商解除而离职 | 核实具体背景与岗位相关影响，不仅凭离职标签或赔偿记录判不推；当前用人方如有此偏好，单独记录并核对依据 |
| 当前岗位要求立即独立交付，已确认缺少培养资源 | 核对当前必需能力与交付证据，说明支持限制；不以潜力替代必需能力 |
| 负责人明确愿意培养，并有可兑现的支持安排 | 区分入职必需能力与可培养项，说明支持人、成长路径和验证节点；不只凭态度判断 |
| 他用「跳槽多 / 某类背景的人都不行」否人 | 先问这条规律来自哪种环境，再判断能否搬到当前岗位和业务周期 |
| 已确认与本岗位要求不适配 | 记录具体差距，可考虑其他岗位；不将当前错配写成人选低质量 |
| 用人方会接，但环境给不了候选人现阶段最需要的东西 | 不推或先披露错配；不能用「先进去再说」掩盖 |
| 候选人过不了这个漏斗，但在别的环境可以成立 | 标记为分流，不写成低质量淘汰 |
| 你自己对递不递拿不准 | 分清缺的是条件还是证据，给阶段性判断和补证动作；不得用确定推荐或淘汰替代待验证，也不要求初次推荐前完成全部后续面试 |
| 他要先拿简历去「问一圈」 | 先核对分享与背景核实的授权范围；可分享的匿名成果可用于讨论任务，但不自动授权转发简历或联系他人，见通用推荐模板 |
| 他不授权、不给 context | 按他能给的东西配人 → `references/hm-os.md` |
| 打分和他对不上 | 做校准 → `talent-read` 第 4 步 |

### 双向适配检查

1. **用人方会不会接**：功能、门槛、属性和否决条件是否通过？
2. **候选人能不能成立**：这个环境能否满足他对下一份工作的期待，支持他的工作方式，并符合他的现实约束？

发现已确认的关键错配时不直接推进；信息不足时标待验证，说明当前可推进的环节与待补证据。推荐要判断这段合作能否成立，不把“没有发现问题”等同于“全部已验证”。
