# 第 6 步 · 递给用人方

## 目标与完成标准
- 先判断这位用人方能给什么、不能给什么，再决定递谁、怎么递
- 同时判断这个环境能否承接候选人的职业阶段任务和工作方式
- 完成标准：递出去的每个名字都过了双向适配，而不是只过用人方的单向安检

## 判断点
| 信号 | 走向 |
|---|---|
| 还不知道这位用人方的否决规则 | 先问出他的否决清单，再过漏斗；不要套用别的负责人的规则 |
| 他不信人会成长（偏法家：只信利益与约束） | 只卖这一期的功能，并配试用期目标等约束机制（硬规则 8） |
| 他相信人能靠后天改变（偏荀子） | 可以卖属性和潜力，同时说明成长路径和验证节点 |
| 他用「跳槽多 / 某类背景的人都不行」否人 | 先问这条规律来自哪种环境，再判断能否搬到当前岗位和业务周期 |
| 人好但过不了他的安检 | 换别的买家，不硬推（硬规则 7） |
| 用人方会接，但环境给不了候选人现阶段最需要的东西 | 不推或先披露错配；不能用「先进去再说」掩盖 |
| 候选人过不了这个漏斗，但在别的环境可以成立 | 标记为分流，不写成低质量淘汰 |
| 你自己对递不递拿不准 | 默认不递，先补证据；拿不准本身就是信号 |
| 他要先拿简历去「问一圈」 | 先给匿名的活，看上了再给名字 |
| 他不授权、不给 context | 按他能给的东西配人 → `references/hm-os.md` |
| 打分和他对不上 | 做校准 → `talent-read` 第 4 步 |

## 模板
- 漏斗判断清单、推荐一页纸（四行）：`references/hm-funnel.md`
- 用人方分型表：`references/hm-os.md`

### 双向适配检查

1. **用人方会不会接**：功能、门槛、属性和否决条件是否通过？
2. **候选人能不能成立**：他的阶段任务、工作方式和约束，能否在这个环境里实现？

只过第一问，不递。高招不是替用人方挑统一排名的「好人」，而是判断这段合作能否成立。
