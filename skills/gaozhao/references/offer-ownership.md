# 钱、编制、审批、锅

内部卡住时，先画四格。空一格，后面全是替位。

这份表帮助核对责任，不替代当前公司的职级、预算和审批制度。下文“补差 / 整包”是两类结构示例，具体可行性要核对实际规则、审批理由与授权，不能把某次审批经验当成所有公司的默认流程。

| 位置 | 必须有人署名 | 缺了会怎样 |
|---|---|---|
| 谁出钱 | 预算主人 | 高价没有合法的家 |
| 谁定级 | 序列主人 + 薪酬口径 | 岗位名还是低档，倒挂算式不改 |
| 谁审批 | 薪酬 / 规则主人 | 他签的是规则，不是人情 |
| 谁承担后果 | 按实际编制、汇报、考核与日常管理明确责任人 | 跨部门用人时，费用承担与管理影响可能落在不同主体，需写清责任边界 |

编制挂在中台、人在项目用——「谁出钱」和「谁被比较」可以不是一回事。薪酬可能关注比较基准，也可能有其他审批条件，先核实实际卡点。

## 两种高价，不是一回事

| | 补差 | 整包 |
|---|---|---|
| 结构 | 项目/原岗该有的价 + 超出部分别处补 | 整包就是这个序列这个岗的价 |
| 比较基准 | 还是原岗同事 | 新序列里已经拿这个价的人 |
| 审批需核对 | 是否属于破例、是否允许及先例影响 | 序列与职责是否真正可比、是否满足当前审批条件 |
| 同事看见的 | 这个人比我们贵一截，公司补的 | 他不是我们这档 |

「编制已经在中台、超出部分公司承担、不让项目出」不自动改变岗位比较基准。若职责与定级不变，仍可能被视为补差；是否如此，要由当前薪酬与序列负责人说明依据。

中台序列里已有同价人员，只能作为核对线索，还要比较职责、级别、预算与审批条件。未获批的原因保持待确认，不直接推定为“仍被当成项目补贴”。

## 为什么薪酬不替你说「编制挂中台 / 超出中台承担」

这类安排涉及编制与预算的责任承诺。先核对谁有权限认领；若薪酬没有相应授权却代为承诺，可能出现：

- 越权（编制是组织动作）
- 变成假结构的作者（对方点头即可，人照样给项目用）
- 把一个主人没要的高价人塞进别人序列

由有权限的责任人明确可承担的安排；补差和整包是否可行分别按当前制度确认，不预设必须整包，也不把口头同意当作责任已落实。

如果薪酬要求预算主人直接参与，先确认其需要对方决定或说明什么。责任人应能回答汇报、考核及管理影响由谁承担；招聘是否参会按实际流程安排，不从参会要求推定对方动机。

## 招聘不该做的

不要当预算主人和薪酬之间的调解人。

你冲上去「说服薪酬」，等于同时替业务和薪酬做担保。任何一边不满意都回到你。

你的产出停在两样，交给主人让他带进门：

1. **四件事填空**：编制 / 汇报 / 考核 / 日常管理——明确实际责任与适用的岗位比较基准；跨部门安排写清边界，不只改费用归属
2. **一句口径**：这个价对应什么职责与级别，依据和审批路径是什么；条件未确认时不代为承诺

会后只认书面回流。口头「聊过了、也同意了」等于没有。含糊 = 不认领。

## 愿意出钱 ≠ 愿意当主人

预算主人可以乐意「为某块能力溢价买单」，同时不想跟项目去盘日常怎么用。出钱止于签字，不含跟进、不含背锅。

挂名在他的组织 + 真主人缺席 = 和「只有 HR、没有主人」同一结构。钱从 A 走，人在 B 用，倒挂仍砸在 B。

测的不是「你愿不愿意出这个价」，是：

1. 这个人汇报给你吗？
2. OKR 挂你，还是挂项目交付？
3. 薪酬那边，你去谈？

含糊时记为责任待确认，补齐负责人及书面安排；不直接认定为补贴，也不由招聘替人认领责任。

## 升级

钱、编制、先例都在仍被否时，先核对实际否决理由，区分岗位比较、预算、制度条件和决定权限。确认是权限或跨部门分歧后，由责任人按当前流程协商或升级；招聘提供证据与责任表，不代拍板，也不默认必须找共同上级。
