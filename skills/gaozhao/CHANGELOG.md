# 高招 skill · 版本说明

## 2.0（2026-11-23）

### 2026-11-24 · 规则一致性修订

- 联系边界：主入口、第 3/4 步与 `star-engage`、`talent-read` 区分停止联系、拒绝当前岗位和弱回应；明确停止后不再安排主动跟进，不以其他渠道或同事绕过。
- 推荐模板：第 6 步与两份用人方参考改为核对当前岗位条件；单个负责人的离职类型偏好和承接限制移入限定适用范围的历史案例，未记录的结果保持未知。
- 样本反馈：`vuca-intake` 与 `talent-read` 将原话、偏好、假设和已确认要求分开；依据任务、替代样本与业务原因验证，由相关拍板人确认变更后再升版，不把一次反馈直接写成门槛。
- 评估状态：补充“待验证、暂不定层”，与已确认不匹配分开；写清下一条证据和可推进环节，取消按固定加分条数决定分层。
- 入口定位：按已知阶段与缺口直接给下一步，只有无法定位或缺失条件会改变动作时才追问；已完成澄清不从头重问。

### 2.0 初版内容

格式不变（第 0 步定位卡点、8 步地图、每步四层、两条线），**主要是补内容和案例**。

**新增主线：长期人才关系**
- 相识于微时：广泛接触后选择性深交，在对方尚未被广泛认可时给出具体的关注与认可（第 3、5 步）。
- 每月标注 3–5 位 Star Candidate，争取逐一面对面深聊；每月复盘信任进展、判断变化、下一步（第 3、5、8 步）。
- 每次交流当天记录；所有候选人统一一张主表，Star 与月度名单从主表筛选（第 3、5 步）。
- 每年发展一位与当年高招主题相关的年度关键链接人，单独登记增量信息、人脉关系和交流节奏（第 2、3 步）。
- 初识冷淡先保留观察；有价值的人持续跟进、保持联系（第 4 步）。

**新增案例**
- 从制作人到增长方向：用市场反馈持续澄清需求（第 1 步）。
- 从弱回应到年度关键链接人（第 2、3、4 步）。
- 从兼职线索到跨场景复用：一段人才关系在高招、校招之间的多次价值（第 2、3 步）。

**口径统一**
- 数字类要求（每月 Star 3–5 人、每个领域 2–3 位专家、每年一位关键链接人、活动前标 3–5 人）都是**建议节奏**，不为凑数降低判断标准。唯一的节奏目标仍是：行业交流线每月至少一次。
- 配套 skill `vuca-intake` 同步调整：排除条件条数、见效周期、每周人选数改为建议节奏，不再是推进门槛；价值观校准改为“底层理念具体化，不要求结论一致”。
- 全文去公司化：不写具体公司内部团队名，案例去人名、去薪酬数字、去内部链接。

## 1.0（2026-10-19）

第一个可以交给团队使用的完整版本。

**结构**
- 第 0 步定位卡点，8 个步骤是地图，可以回退。
- 每一步四层：目标与完成标准 / 判断点 / 模板 / 案例。
- 两条线并行：岗位线（第 1–8 步）和行业交流线（寻源 → 触达 → 安排交流 → 长期关系）。只交流、不招聘也算完成；节奏目标是每月至少给业务一号位安排一次。

**各步骤的核心内容**

| 步骤 | 核心 |
|---|---|
| 1 需求澄清 | 硬门槛与属性分开；用杠杆三问判断：这个岗位要的是把事做好的人，还是替你拿主意的人 |
| 2 寻源 | 情报 → 定位 → 落成名单，终点是具体的人；七类渠道（行业活动、公开分享、行业媒体编辑、内部对外岗位同事、领域专家网络、猎头、招聘平台）；猎头和编辑关系平时养；每个领域 2–3 位内外部专家；行业线索记录与核实 |
| 3 触达 | 先有对方高优先级需求的假设；行业交流线开场给真实价值；着眼长期关系，不为一次招聘损害信任 |
| 4 动机核实（强制） | 第一次接触就先问期待的下一份工作，再讲 JD，原话记日期；问清下一份工作的期待：想得到什么、摆脱什么、证明什么、走向什么角色；专长；对方决策模型 |
| 5 评估分层 | 证据三级；多场景交叉验证；高杠杆岗位额外看判断力、担责、杠杆；竞争性假设 |
| 6 递给用人方 | 双向适配；按用人方的人性假设决定怎么递；过不了安检的走别的买家 |
| 7 Offer 与内部结构 | 钱、定级、审批、后果四格都有主人；关键承诺写成书面约定；多 offer 摇摆时对照初心原话 |
| 8 复盘与沉淀 | 判断与结果对账；真案带教闭环；每月回看：为业务促成了哪些外部同行交流，有什么收获 |

**专题资料**
- 人才地图与竞品动态监测：六步法，含内部核心人才的流向。
- 用人方漏斗、负责人操作系统、Offer 责任归属。

**底层原则**：长期博弈、本质优先于附带结果、信任加机制、情报式判断法，以及各自的迁移边界。

**已知缺口**
- 多数步骤的案例层待补，目前只有一个真实案例（行业交流转化）。
- 第 2 步样本反馈记录表待补。
- 用人方漏斗和负责人操作系统中的否决规则来自单个负责人，是案例，不是默认值。
