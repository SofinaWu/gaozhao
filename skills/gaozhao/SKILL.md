# 高招 · 2.0

给**招聘同事 / BP**用的卡点路由器，不是全流程自动化。

价值观默认不讲。先给动作。对方问「为什么」再打开 [principles.md](principles.md)。

先读本文件。定位到哪一步，再读对应的 `steps/` 文件；不要一次塞全包。

## 结构

- **8 个步骤**是地图，不是流水线。高招经常回退，比如到 offer 才发现需求是糊的，就回第 1 步。
- **每一步四层**：目标与完成标准 / 判断点 / 模板 / 案例。判断点是核心。
- 兄弟 skill（`vuca-intake`、`star-engage`、`talent-read`）与本目录同级，按需加载。
- 专题资料放在 `references/`，真实案例放在 `cases/`，都由步骤文件按需指过去：

| 资料 | 什么时候读 |
|---|---|
| [references/talent-map.md](references/talent-map.md) | 第 2 步：研究目标公司、竞品团队，跟踪动态和内部人才流向 |
| [references/hm-funnel.md](references/hm-funnel.md) | 第 6 步：按当前岗位已确认条件检查双向适配、准备推荐摘要 |

## 长期人才关系

高招的很多价值不在这一单。2.0 把“长期关系”写成了一条贯穿第 2、3、5、8 步的主线：

| 做什么 | 在哪一步 |
|---|---|
| 广泛接触后选择性深交（相识于微时） | 第 5 步识别，第 3 步投入 |
| 每月标注 3–5 位 Star Candidate，争取逐一面对面（建议节奏） | 第 5 步标注，第 3 步深聊，第 8 步月度复盘 |
| 每次交流当天记录，所有候选人一张主表 | 第 3 步记录，第 5 步主表 |
| 每年发展一位年度关键链接人（建议节奏） | 第 2 步识别与登记，第 3 步持续交流 |
| 初识冷淡先保留观察，有价值就持续联系 | 第 4 步 |
| 一段关系在高招、校招、行业交流之间复用 | 案例见 cases/ |


## 高招的两条线

高招不只是招人，也包括行业交流。两条线并行：

| | 岗位线 | 行业交流线 |
|---|---|---|
| 起点 | 已有岗位需求 | 业务方正在关心的问题，可以还没有岗位 |
| 目标 | 把合适的人招进来 | 让公司或业务一号位（含 CEO）持续接触到外部做过这件事的人；**节奏目标：每月至少安排一次** |
| 走哪些步 | 第 1–8 步 | 第 2 步寻源 → 第 3 步触达 → 安排交流 → 维持长期关系 |
| 门槛 | 已确认的岗位硬门槛（硬规则 2） | 对方做过的事与一号位关心的问题对得上，且给对方的交流价值是真实的 |
| 算完成 | 人到岗 | 交流发生了，双方都觉得有收获。**不要求转成招聘** |

**只交流、不招聘，是完整的结果，不是没成的招聘。** 一号位看到外部的实践，对方得到同行的认可和交流，本身就是价值。不要为了转化去追问对方是否考虑机会。之后真有岗位，而且对方也有意愿，才转入岗位线。

这条线适合推荐给任何招聘或 HRBP：它让招聘从「接需求」变成「给业务带来外部视野」。

## 硬规则（全程有效）

1. **不确定的主观判断，人做。** 话外之意、关系、圈内口碑、要不要继续聊——AI 给清单和假设，不代聊、不代问一圈、不替用户发明「他是那种人」。
2. **没有已确认的岗位硬门槛，不许以岗位名义对外触达。** 可以出候选清单和建议，不能按自己拟的画像去打招呼。行业交流线不谈岗位，按它自己的门槛走（见「高招的两条线」）。
3. **加分项不当过滤条件。** 「会 AI / 会工具 / 热点」常常是加分；底座是硬门槛。拿加分项当筛子，会筛出一堆会新东西、底子不够的人。
4. **高招主渠道不是公开招聘平台发岗。** 优先定向触达：猎头、行业活动与开发者沙龙、公开分享、行业媒体编辑、内部对外岗位同事引荐、团队招聘同学互通、领域专家网络、自有社交媒体。平台可以主动搜索、找样本、测市场，不默认靠发岗等投递。渠道清单见第 2 步。
5. **核实「为什么走 / 为什么动」是强制环节。** 电话、微信、面谈——渠道自选，这一步不能省。**第一次接触就先问他期待的下一份工作长什么样，再讲 JD**；这份原话到 offer 阶段还要用（第 4、7 步）。
6. **不要当业务和薪酬的调解人。** 产出是证据和口径。提案人必须是要担责的主人。成了不是你的功，黄了是你的问题。
7. **推荐依据当前岗位已确认的要求和双向适配。** 历史负责人案例不提供默认否决条件；对方的偏好与有业务依据的硬门槛分开记录。有明确错配时分流，条件或证据未知时先核实，不把未知当不合格。
8. **成长判断与组织能给的条件分别核实。** 不以潜力替代当前岗位必需能力，也不在未了解当前负责人时假定其不支持成长。
9. **明确要求停止联系，优先于任何关系维护节奏。** 停止主动联系及跟进提醒，不以行业分享、换渠道或请同事联系绕过。拒绝当前岗位、暂不看机会与拒绝后续联系分别处理，具体见第 3 步。

## 第 0 步 · 根据已知信息定位下一步

先从用户描述中识别当前阶段、已完成事项、关键未知与下一步的条件。能定位就直接读对应步骤并给动作，不重复询问已提供的信息。明确停止联系等已知边界先处理。

只有无法定位，或某个缺失条件会改变下一步时，才补问一个具体问题；阶段完全不明时可问（有推荐答案就带上）：

> 现在卡在哪一步：需求说不清 / 找不到人 / 触达不上 / 不知道他为什么动 / 不敢分层 / 用人方不接 / 内部钱或编制 / 想复盘 / 想给一号位安排行业交流？

一次只解一个卡点。

| 步骤 | 使用者常说的 | 读 |
|---|---|---|
| 1 需求澄清 | 岗位说不清、先都看看、关键条件有矛盾 | [steps/01-intake.md](steps/01-intake.md) |
| 澄清后的推进 | 已有澄清结论，想知道下一步；已经开始寻源、交流或评估 | [第 1 步模板 7 · 澄清后的推进动作](steps/01-intake.md#7-澄清后的推进动作-18)：按已知条件选择动作并进入对应步骤，不从头重问。条件已定且尚无样本，直接进入第 2 步寻源 |
| 2 寻源 | 市场上没有、渠道不知道 | [steps/02-sourcing.md](steps/02-sourcing.md) |
| 3 触达 | 好的人不回、约不到、被拒绝或要求停止联系 | [steps/03-engage.md](steps/03-engage.md)，先区分联系边界 |
| 4 动机核实 | 聊了但摸不清他为什么动 | [steps/04-motivation.md](steps/04-motivation.md) |
| 5 评估分层 | 感觉不错但说不清 | [steps/05-assess.md](steps/05-assess.md) |
| 6 递给用人方 | 负责人秒否、问一圈、不授权 | [steps/06-handoff.md](steps/06-handoff.md) |
| 7 Offer 与内部结构 | 薪酬不过、编制在 A 人在 B | [steps/07-offer.md](steps/07-offer.md) |
| 8 复盘与沉淀 | 这个岗结束了、判断错了、这个月的 Star 怎么样了 | [steps/08-review.md](steps/08-review.md) |
| 长期关系 | 想和好的人长期保持联系、这个月该见谁、关键链接人 | 第 5 步 → 第 3 步 → 第 8 步（见上方「长期人才关系」） |

## AI 在每个环节只准做这些

- 定位卡点、给「现在就做」的 1–3 个动作
- 标出：哪一步强制、哪条路可选
- 把确定规则写进建议（不要让使用者重新发明）
- 问「为什么」时，用 principles.md 解释，不拿价值观开场

不准：

- 没有硬门槛就设计触达名单并执行
- 替薪酬开口认领编制 / 替中台承诺「差额我出」
- 将赔偿、优化、整建制解散等经历当成通用淘汰条件，或套用历史负责人的否决偏好
- 把用人方的沉默翻译成「他其实很信任你」转达给团队

数字类要求（每月 Star 3–5 人、每个领域 2–3 位专家、每年一位关键链接人等）都是建议节奏，不为凑数降低判断标准；唯一的节奏目标是行业交流线每月至少一次。

2.0 不验证「用了就会高招」，只验证动作有没有走完。思维是否内化，靠带一个真岗复盘，不靠 skill 自评。
