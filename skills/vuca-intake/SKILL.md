# VUCA 需求澄清

把一个模糊的招聘需求跑成清晰的、有证据链的人才画像。

> 核心认知：**VUCA 的招聘需求，本质是一个还没被解决的业务问题。**
> 用人方不是懒得写 JD，是他自己还没想清楚。你的交付物不只是人，是**帮他想清楚的过程**。
> 因此：**需求会变是正常的，方向调整是收敛，不是返工。**
>
> 合作底座：先给样本、判断和理解力，不把交付变成「你应该听我的」的隐形账单。与此同时，共创所需的 context、反馈和决策要提前说清；这是明示的工作契约，不是人情债。

## 第 0 步 · 判断是否适用

命中 ≥2 条才用本 skill，否则走常规 JD 招聘：
- 没有具象 JD，或有 JD 但用人方说「不够到位」
- 没有明确的人才寻访方向
- 新业务，用人部门自己也不熟这个领域
- 用人方说「先都看看，别框死」
- 要解决的问题很多，说不清哪个优先

同时判断是哪一类 VUCA，处理方式不同：

| 类型 | 表现 | 处理 |
|---|---|---|
| 问题复杂/抽象 | 只能说「想解决 XX」 | 从问题反推能力，不从头衔出发 |
| 涉及现有团队影响，不便明说 | 回避某些追问、强调保密 | 别硬追，做旁证：现有团队缺口、谁在兼这个活 |
| 用人方习惯先散后聚 | 主动说「先都看看」 | 顺着走，但必须做记录，否则散完无法收敛 |

## 第 1 步 · 需求沟通（引导用户去问，或陪用户复盘已问到的）

**目标不是拿到画像，是拿到「问题」和「排除条件」。**

### 必问 9 题
1. 这个岗位存在，是因为什么问题没被解决？没有这个人，现在谁在扛、扛得怎么样？
2. 他来了之后，三个月后哪件**具体的事**会变得不一样？（不要「提升效率」这种）
3. 为什么是现在招？为什么不是半年前 / 半年后？
4. 向谁汇报？和谁抢资源？
5. **哪些人是明显不合适的？**（要 ≥3 条 —— 这题的答案通常比「要什么样的人」清晰十倍）
6. 如果只能满足一条要求，你保哪条？
7. 上一个做类似事的人为什么没成 / 为什么走了？
8. 需要他自己动手落地，还是只出策略？（**务必问**，很多决策人自己就是动手型，会默认这条却不说）
9. 价值观校准：对同一件事的归因思路是否需要一致？（视角可以不同，价值观必须一致）

### 同时记录潜台词（明说 / 推断分开写）
- 反复强调的软性词（「聪明」「靠谱」「胆子大」）→ 那是真标准，且他自己定义不出来。**你的工作是替他定义它**
- 对某类背景反应特别快（正或负）→ 有历史包袱，去问那段历史
- 说「都可以看看」但只对某一类给正反馈 → **信反馈，不信开场陈述**
- 回避了哪个追问 → 大概率涉及团队内部影响，做旁证

## 第 3 步 · 用样本换需求（最关键的动作）

抽象追问「你到底要什么样的人」得不到答案。**给他具体的人去反应。**

1. 按「问题」而非头衔，列 **3-4 个不同方向**的人才假设（例：从研发侧解 / 从商业化侧解 / 从数据侧解）
2. 每个方向找 3-5 个具体的人（公开信息即可，不必已接触）
3. 带回去只做一件事：**让他排序并说理由**
   - **反对的理由信息量 > 赞同的理由**
   - 他理由里出现的词，就是他的真实标准
4. 当场把新标准写进澄清表，升版本

## 第 4 步 · 常态运转

| 频率 | 动作 |
|---|---|
| 每周 | 确保决策人**至少有一位 qualified 人选**可交流。**量变产生质变**——他见得越多，标准越清晰。这条比任何追问都有效 |
| 每轮寻源后 | 写三段式：关键信息提取 / Deliverables / Findings / Conclusions |
| 方向调整时 | 澄清表升版本，保留旧版 |
| 每轮面试后 | 从通过者反向提取真实标准，回填画像 |

## 心态基线（对新手最重要的一段）

- **没有 ddl、一切未知，一开始一定会焦虑**——这是这类需求的固有属性，不是你能力不足
- **胆子大一点，去繁为简**，在动态过程中摸方向。要求自己一开始就找到正确方向 = 卡死
- **不懂就问，不怕犯错**。暴露自己的不懂是一种**交底行为**，是建立信任的关键，不是丢脸
- **主动表达，先打开自己**。等着对方把需求说清楚再动，永远等不到

## 失败模式（自查）

| 失败模式 | 修正 |
|---|---|
| 等需求清楚了再动 | 先给样本，用样本换需求 |
| 把方向调整当返工 | 前几轮的 findings 就是资产 |
| 只记结论不记过程 | 三段式 + 澄清表版本号 |
| 信开场陈述不信反馈 | 每轮从反馈反推真实标准 |
| 澄清做成审问 | 姿态是「一起解题」，不是「你说清楚我才干」 |
| 把交付变成人情筹码 | 样本和 findings 用于换信息，不用于换服从；协作条件提前明示 |
| 需求方不愿参与还硬做 | 见下 |

## 何时该拒接 / 明确边界

需求方**不愿意一起想清楚**（不给时间、不给反馈、不接受方向调整、只重复「你按 JD 找就行」）
→ 这不是 VUCA 需求，这是无底洞。明确说出边界。

## 环境依赖（外部客户场景必读）

本方法的高效运转依赖能拿到**充分真实的一手 context**（透明的沟通环境、决策人日志、项目信息）。
不具备时的降级路径：
- 拿不到一手 context → 用**公开产出**反推：这家公司近半年发了什么、招了什么人、组织变了什么
- 拿不到决策人时间 → 「每周一位人选」降级为「每两周一份带三个候选画像的对比问卷」，用书面反馈换判断
- 拿不到内部旁证 → 从**离职者与外部合作方**取证
