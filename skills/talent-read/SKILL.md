# 属性维度读人

把「感觉这人不错」推进成**可解释、可校准、可传授**的判断。

> 核心认知：**看技能是用来解决已知的问题，看属性是用来解决未知的问题。**
> 岗位越模糊，属性权重越高——因为你不知道他将来要解什么问题。

## 硬规则（不遵守就退回 L1「感觉」）

**每条判断必须挂一条具体证据**：他说的哪句话、做的哪件事。
不许只写「逻辑清晰」「沟通不错」这类无证结论。

**候选人质量与关系状态必须分开。** 回复快不快、是否接受流程、有没有马上转介绍，只说明当下意愿和约束，不直接证明能力、诚信或感恩程度。单次没有回报不等于单向索取；长期重复索取且不尊重边界，才可作为关系模式记录，而且不能混进岗位能力分。

判断的三层，目标是把所有判断推到 L2 以上：

| 层 | 形态 | 可传授 | 可校准 |
|---|---|---|---|
| L1 感受 | 「这人不错」 | ❌ | ❌ |
| L2 信号 | 「他能区分事实与推断，且主动指出了岗位风险」 | ✅ | 部分 |
| L3 系统 | 信号清单 + 权重 + 分层定义 + 与 HM 的校准记录 | ✅ | ✅ |

## 第 1 步 · 定权重

技能是**门槛**（能不能干这活），属性是**排序**（未来能长成什么）。
**先过门槛，再用属性排序。** 倒过来会招进「人很好但干不了」。

| 岗位性质 | 技能:属性 | 理由 |
|---|---|---|
| 成熟岗位、已知问题、标准流程 | 7:3 | 要立即产出，技能可直接验证 |
| 新业务 / 无成熟 JD / 方向会变 | 3:7 | 他要解的问题现在还不存在 |
| 近身岗位（一号位副手、业务助理） | 2:8 | 相处成本与价值观一致性决定成败 |
| 前沿技术岗 | 4:6 | 技术栈半年一换，学习速度比现有栈重要 |

以上比例用于讨论侧重，不是默认打分公式；权重须结合当前任务与用人方校准，不能用高属性分抵消必要能力缺口。

## 第 2 步 · 按信号清单读

### 加分信号

| 属性 | 可观察表现 | 怎么问出来 |
|---|---|---|
| 逻辑思维 | 回答有结构；能区分事实 / 推断 / 猜测 | 让他讲一个复杂项目的决策过程 |
| 表达能力 | 能把复杂的事讲给外行听懂 | 让他解释一个你不懂的技术选择 |
| 识别问题的能力 | 主动指出你没问到的关键点 | 「这个岗位你觉得最大的风险是什么」 |
| 解决问题的能力 | 讲得出具体动作与取舍，不只讲结果 | 「当时有哪几个选项，为什么选这个」 |
| 胆子大 / 乐于接受未知 | 主动选过高不确定性的路 | 「你做过最没底的一个决定是什么」 |
| 抗压且不轻易否认自己 | 被质疑时能坚持思考后的结论，也能被说服 | **在压力面里给一次反对意见，看他怎么接** |
| 能平等对话 | 不谄媚、不对抗，有自己的判断 | 观察他怎么处理你和他的观点分歧 |
| 拿结果能力 | 使命必达的历史证据 | 「有没有一件事你明知很难还是做成了」 |
| 归因方式健康 | 归因到自己可控的变量 | 「上一个项目为什么没成」 |
| 视角宽广 | 介入过产品全历程，尤其初期就介入 | 「你是什么阶段进去的」 |
| 数据素养 | 知道什么阶段该看什么数据（不是会用工具） | 「那个阶段你主要盯哪几个指标，为什么」 |

### 扣分信号

- **沟通很负面**：对前雇主 / 同事 / 行业普遍性抱怨
- **对问题的认知很表面**：只能复述现象，说不出机制
- **归因模式化地指向环境** → 见下
- **不敢暴露不懂**：宁可含糊也不说「这块我不熟」——对高潜岗位是硬伤
- **只讲结果不讲取舍**：大概率没真正做主

### Serial complainer 线索与核实

> 问：**「上上家和上家分别为什么离开？」**
> 如果理由反复指向环境，先记录为待验证线索，追问每段经历中的具体事件、本人能控制的部分，以及实际采取的动作。

边界：多次遇到环境问题也可能是真的。看跨情境行为与可核实事实，不仅凭离职理由的表述给人贴标签；证据不足保持待验证。

## 第 3 步 · 分层

先区分岗位适配与证据充分度。“尚不了解”不能直接归为“不匹配”；信号数量不作为固定分层门槛，重点看证据质量、岗位相关性和是否经过不同情境验证。

| 结论 / 评估状态 | 定义 | 动作 |
|---|---|---|
| **Star** | 能力突出，关键属性有跨情境证据支持，无已确认硬扣分；能与决策人平等讨论关键问题 | 结合意愿优先交流并经营长期关系；推荐具体岗位仍需核对其门槛与双向适配 |
| 可推 | 岗位门槛达标，关键证据足以支持当前推荐环节，重要未知已说明 | 按当前环节推进，不把推荐等同于所有评估已完成 |
| 待验证（评估状态，暂不定层） | 门槛已达标或仍待核实，已有线索但不足以下稳定属性或推荐结论，且没有已确认的不适配依据 | 写清已有证据、缺口、下一条验证和当前可推进环节；可继续专业面或补关键事件，不以证据少自动淘汰或归为不匹配 |
| 观察 | 有可解释的亮点，但已确认当前岗位或时机不匹配 | 记录具体不匹配之处，结合本人意愿保留关系，不自动安排季度联系 |
| 不推 | 已确认有与岗位相关的硬扣分，或不满足已确认的必要门槛 | 记录事实、适用岗位与原因，闭环；不能只凭离职标签或未验证疑点下结论 |

例如：技能达标、未见扣分，只有一条可信的属性信号，先给“待验证”的阶段性判断和下一步证据，不凑加分条数、不伪造稳定品质。任何分层或入池都不授予联系权限；明确要求停止联系时，停止主动联系和提醒，不换渠道或请同事联系。

**选择性投入**：80/20 是投入侧重的示意，不是固定比例或人选配额；按证据、相关性与双方意愿分配时间，不因分层或排期获得联系权限。

## 第 4 步 · 与用人方校准（必做）

> **用人方的打分系统可能和你不一样，需要相互校准。**
> 不校准的后果：你推的人全被否，或你筛掉的正是他要的——而双方都以为对方不专业。

1. **锚点法**：用有差异的具体样本，请他排序并说理由（可参考 2–3 人）。记录原话与偏好，不直接将其定义为必要标准；用任务、业务原因和替代样本检验。
2. **词义对齐**：他说「聪明」时，请他举一个他见过的「聪明」的例子。不要假设你们同义
3. **分歧留档**：判断不一致的案例单独记——这是最有价值的校准素材
4. **每轮面试后回填反馈与待验证解释**。硬门槛、属性、背景偏好分别记录；改变岗位要求须有依据并经相关拍板人确认，再升版，不因一句偏好自动筛人。
5. **落地权重问清**：他要的是策略还是自己动手

## 第 5 步 · 闭环（不做这步，聊 1000 个人也不会更准）

1. 聊完及时写一句话阶段性判断、依据与评估状态；证据不足时分层写“未定”，保留缺口和下一条验证
2. 事后回捞：进了流程的人后续表现如何，**你当时的判断对了吗**
3. 从对与错里反向提取信号，更新信号清单
4. 对照通过与未通过样本及后续实际表现，检验原先信号是否有效；录用或拒绝本身不证明标准正确。新解释先记待验证，岗位要求变化按第 4 步确认后回填需求澄清表。

建议节奏：每月抽 3 个已入职或已拒的人，对照当初判断做一次校验。

## 深挖动机（这部分最难，但决定留存）

技能匹配决定他**能不能干**，动机匹配决定他**会不会走**。

要拿到的：职业规划、个人理想、人生目标、约束条件（家庭 / 地域 / 时间表）。

怎么拿到：
- **区分初步期待与深入核实**：说明招聘来意且对方愿意讨论机会后，可在展开 JD 前了解其自愿表达的下一份工作期待；更深的规划、私人约束随信任与意愿逐步了解，不要求首聊拿齐。纯行业交流不强行问求职动机
- **分享式而非审问式**：先说你自己的观察与判断，他才会说他的
- 你不懂的直接说不懂——暴露自己是建立信任的方式

**受托信息红线**：候选人的动机、规划、约束、薪资都是受托信息。
不外传、**不用于压价或谈判施压**、不进对外材料。破一次，圈子里就没了。

## 失败模式（自查）

| 失败模式 | 修正 |
|---|---|
| 用属性给技能不足的人开后门 | 技能是门槛，先过门槛 |
| 把「聊得投缘」当属性判断 | 投缘是你的舒适感。找反例：他哪一点让你不舒服，那才是信息 |
| 属性判断无法向用人方解释 | 每条判断挂具体证据 |
| 仅凭离职理由就判 serial complainer | 核实具体事件、本人动作与其他解释；重复表述不等于已证实的稳定属性 |
| 只记结论不记当时证据与状态 | 当场记录阶段性判断与依据，分层可未定，事后对照验证 |
| 假设用人方与你同标准 | 锚点法 + 词义对齐 |
| 对方没马上回报就扣品格分 | 即时回应不是属性证据；关系状态与候选人质量分开记录 |

## 输出格式

评估一个人时按这个给：

```markdown
## <姓名> · <应聘岗位>
**评估状态**：当前证据足以支持本轮结论 / 待验证
**分层**：Star / 可推 / 观察 / 不推；证据不足时写“未定”，不硬塞进四档
**一句话判断**：

### 门槛（技能层）
| 项 | 达标 / 不达标 / 待核实 | 证据 |

### 属性信号
| 属性 | 加/扣 | 具体证据（他说的哪句话/做的哪件事） |

### 动机与约束
- 动机 primary：
- 约束条件 / 时间表：

### 关系状态（不计入能力分）
- 当前意愿与互动节奏：
- 已表达的边界：
- 长期互动模式（证据不足则写「待观察」）：

### 风险与待验证
- 已有证据与未决假设：
- 下一条需要的证据及验证方式：
- 当前可以推进的环节 / 需先解决的缺口：

### 与用人方可能的分歧
```

## 配套

判断依赖尚未明确的岗位要求时，用 `vuca-intake` 补齐相关条件；已有结论沿用，不重跑澄清。没有具体岗位时也可依据行为证据评估长期关注价值，岗位适配留待有需求时再核对。
